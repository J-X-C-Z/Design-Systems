## State, keyboard and action contracts

All four accept exclusive value/defaultValue of their exact union|null (default first), onValueChange(next,details), disabled, activationMode automatic/manual, orientation horizontal/vertical, dir ltr/rtl, loop, label, triggerProps/listProps/panelProps and root div native attrs/ref. Tabs14 defaults horizontal;15/16/17 default vertical. Details include exact id, previousValue, reason click/focus/keyboard, actual event/button and cancel(). False or event.preventDefault() vetoes a selection. Controlled owners win; release retains the latest committed value; later defaults do not reset an instance. These are not form fields; native form reset does not reset tab selection.

Axis arrows/Home/End navigate every eligible DOM button, including all8 ofTabs14, with RTL/loop handling. Automatic focus selects; manual focus waits for Enter/Space/click. Tab remains native. Cancellation, newer owner/configuration, unmount, disabledness and explicit external focus supersede queued interaction. Hidden associated panel shells remain but inactive content/actions unmount. Conditional focus return follows the latest owner without automatic re-selection; reopening the old panel cancels stale return. Native/synthetic event methods restore exactly. React19 root/list/trigger/panel/action cleanup refs are supported. The thirtieth-controls owner/cancellation/availability engine is byte-preserved.

Only Tabs16/17 add actionProps[value][action] native button attrs/ref and onAction(action,details). Tabs16 action is deploy;Tabs17 actions are book/profile. Details hold exact id/value and the actual MouseEvent/button. Native button onClick runs synchronously before ancestor propagation; deferred onAction notifies only if uncanceled, enabled, connected and still current. Snapshot occurs before the caller handler. Noncontrolled already-accepted logical selection invalidates an old panel action even before commit; controlled rejected selection leaves the old panel current. Owner change/release/unmount and committed disable→reenable invalidate old requests. Return value is ignored: this is an intent notification with no default backend operation or fake success. The parent may ignore/record it. Root and per-action disabledness apply; disabling a navigation tab alone does not disable independent active-panel actions. Enter/Space/Tab use native button behavior, with no duplicate synthetic keyboard click.
