# Xiaomi MiMo 网站设计语言提炼 — MiMo Design Language Study v1.0

> 研究日期：2026-10-10  
> 用途：个人独立设计资源库 / 跨网页、应用、演示、文档复用的设计参考。**非小米官方设计系统；非 SP 主题配置；不与 Lumina 或 Noema 混用。**  
> 方法：参照 Claude Design 的「导入真实资产 → 提炼系统 → 在不同场景生成并验证 → 迭代」方法。  
> 状态：**研究性提炼 v1**，适合作为原创设计系统的起点；未获得官网生产 CSS / 字体文件 / 完整动态录屏，不应把下文建议数值误当成官方精确规范。

---

## 0. 核心结论

**MiMo 的共同设计基因不是某个固定色板，而是“克制的界面底色 + 强烈的内容层级 + 技术工具的直接性 + 带有人情味的表达”。**

它在不同站点表现为不同的场景语汇：

1. **Research / Editorial（研究编辑式）**：巨幅招呼式排版、重复字标底纹、长篇叙事、细线与编号列表；以文字、研究内容与信息节奏构成视觉。
2. **Developer / Humanist（开发者人文式）**：安装命令、终端、文档结构与柔和纸面；兼具工程可信度和面向人的亲和感。MiMo Code 中还可见带水墨/笔触气质的图像元素。
3. **Workspace / Rational Humanistic（理性人文工作区）**：大面积留白、弱边框、输入主导、少量分层和任务状态，界面本身后退，操作成为主角。
4. **Workspace / Dark Tech（暗黑科技工作区）**：深色工作区、清楚的操作层级、低饱和界面与局部强调。**官方明确在 Studio 更新日志中使用「理性人文」「暗黑科技」这两个名称**；将它们扩展为整个个人设计库的分支，是本文的设计归纳，不是小米发布的跨全站主题规范。

应保留：高对比、直接排版、内容驱动分区、轻量线条和箭头、工程语义、按需增强的动效。  
应避免：把 MiMo 简化为黑白极简或固定三栏卡片布局；让每个页面都用一样的大标题；把 Noema/Lumina 的 Token 套入其中。

## 1. 研究方法与可信度

### 1.1 Claude Design 式步骤

1. **Collect / 收集**：从官方研究主页、模型发布页、Code 落地页、Code Docs、科学研究叙事页、Studio/Claw 更新日志、Desktop 官方图像与产品页收集证据。
2. **Observe / 逐页拆解**：对每一页面记录：首屏信息层级、宽度与网格、文字角色、色彩角色、表面层级、CTA、内容组织、动效线索、场景职能。
3. **Distill / 提炼稳定模式**：区分多站点共性与特定产品的局部表达；不把只在一处出现的图像或强调色写成品牌底层规律。
4. **Cluster / 分支聚类**：按“研究叙事—开发者工具—工作区”组织可复用的场景语汇；官方浅色/深色双模式作为工作区分支的依据之一。
5. **Translate / 形成可用语言**：总结语义 Token、字体层次、排版策略、组件原型、动效语言和图形素材库。
6. **Validate / 跨场景验证**：使用同一套候选规则制作研究封面、开发者落地页、文档、AI 工作区，检查换内容后是否仍可辨识且可用。

> Claude Design 官方：真实样例往往比孤立色板更有价值；其完整设计系统通常包含颜色、字体、组件和布局模式，建议使用实际生成场景检查提炼结果。[R01]

### 1.2 证据分级

- **A 级：官方页面结构/官方文字**。例如研究主页的 “HELLO, I'M MiMo”、大量 01/02 编号条目、模型/博客层级、Code 的安装命令、研究页的交互式 3D 结构。[R02][R03][R04][R06]
- **B 级：官方发布的视觉资源或更新记录**。例如 MiMo Code 官方 feature 截图、Desktop 文档中的产品 UI 截图、Studio 对两种风格和音频/滚动动画的更新记录。[R07][R08][R09]
- **C 级：可检索的第三方网页截图**。用于辅助识别历史视觉表现；可能落后于最新版本，不反推当前准确尺寸和颜色。[R10][R11]
- **D 级：本文提出的“个人设计语言建议”**。数值 Token、动效时长、组件名称、排版比例均属于候选方案，须经过后续实测和原创案例验证。

### 1.3 本次限制

官方站点动态页面不能在本次研究环境中通过浏览器完成所有交互/手机端截图，未取得生产 CSS、精确字体声明和动画时间线。本报告**不声称**已像素测量全部站点或验证全部 hover / 滚动特效。涉及动效的描述会明确区分「可从文档确认」与「建议重构」。

## 3. 跨站点共用的 Design DNA（核心不变量）

### 3.1 清晰胜过装饰 / Clarity First

页面的第一阅读路径常是**极强的标题 → 一句功能解释 → 明确下一步操作**。工具页面通过命令、输入或按钮直接完成行动；研究页面通过导语、分节、编号引导阅读。视觉装饰通常不是核心信息承载者。

### 3.2 文字即视觉 / Type Is Architecture

“HELLO, I'M MiMo”不是普通标题：它成为整个页面的视觉锚点。官网的纸面感与重复字标背景证明，字形可承担纹理和构图角色；代码页则在常规标题外使用终端命令构建技术气质。无需复制字样，可以借鉴**巨幅展示字、短英文导航标签、细微字距和代码字体切换**。

### 3.3 简洁界面 + 富有内容 / Minimal Shell, Rich Content

MiMo 并不是所有页面都“空”。技术文章有数据、图表和长段落；文档有多层导航；工作区则包含任务面板。共性不是减少内容，而是**在内容复杂时维持清晰容器和可扫描层级**。

### 3.4 理性秩序 + 人文感 / Rational + Human

结构性的编号、时间、箭头、代码与科学可视化体现工程理性；问候、团队叙述、温和底色和开发者友好的提示降低冷漠感。这个组合比“纯未来科幻”更能表达 MiMo 的独特性。

### 3.5 场景优先 / Contextual Density

研究页面可以宽阔而有节奏；文档必须高密度、可定位；AI 输入界面应减少干扰。**同一设计语言可以有不同密度和控件复杂度**，不该强制所有产品采用同样卡片尺寸。

### 3.6 对比、编号、箭头 / Contrast, Index, Direction

研究主页与 Desktop 官网都有大量编号 01/02；列表搭配箭头；强对比按钮或命令可复制区作为行动焦点。这些是跨界面的弱品牌标记，比特定颜色更加可迁移。

## 4. 五个研究维度

### 4.1 色彩 / Color Semantics

**观察**：主站和 Code 暗示高明度白/暖白、深黑文字、轻灰辅助层；Studio 历史版本既有浅色也有深色，官方确认两种视觉风格。Code 官方 UI 有较明显暖橙点缀，平台与 Claw 某些功能出现蓝色/金色营销强调，但这些不是全系统一主色。[R02][R03][R07][R09][R10]

**提炼**：一个中性基础色系统 + 按产品场景使用少量强调色。

推荐语义角色：`canvas`, `surface`, `surface-raised`, `ink`, `ink-muted`, `hairline`, `accent-functional`, `accent-expressive`, `focus`, `success`, `caution`。不把任何单个 Hex 当作“官方 MiMo 的规定值”。

### 4.2 字体 / Typography

**观察**：研究页具有具视觉冲击的展示标题；论文/博客偏向更传统的文章层级；Code 页面中，终端安装命令形成强烈的等宽字辅助声部；多语言并存。[R02][R03][R04]

**提炼**：

- Display：大字号、较紧凑的标题，可使用现代无衬线作为起点；少数长文引言可探索适量有衬线字体的对照，但**不是官方字体声明**。
- Heading：清晰层级而非每级都超大。
- Body：舒适阅读、长文行宽受控、中英文兼容。
- Meta：编号、日期、导航、小标签可使用小字号与字距形成次要“技术”声部。
- Mono：命令、代码、参数与数据；不将整站都切成等宽字体。

准确字体家族、字重、字号需要后续有权限的网页测量，现阶段只提供可替换的 fallback stack。

### 4.3 网格与空间 / Composition

常见“宽留白 / 薄分割 / 清楚区段”。研究页有大型 hero、列表式论文与文章区块、编号章节；Developer Docs 为侧栏 + 内容主列；Workspace 则以对话/编辑区域为重心、导航与配置退居次要。

不强制使用固定 12 栏系统；把 **Editorial Grid / Reading Column / Workspace Shell** 当成三种场景构图策略。

### 4.4 材质与图形 / Material

- Editorial：重复品牌字、极细线、低对比图案、局部大字。
- Developer：命令行、代码窗口、终端 UI、笔触或水墨式产品视觉素材（以 MiMo Code 官方 feature 图为例）。
- Research：精确的数据图表、结构示意、可操纵模型。
- Workspace：低对比容器、圆角输入、浮动弹出、界面分层。

这些材料是可选特征，不应将“使用水墨”写成所有 MiMo 页面必须遵守的规则。

### 4.5 情绪 / Tone

基础气质：**calm, capable, deliberate, human**（冷静、可靠、克制、亲近）。  
区分：Research 强表达，Developer 强工具，Workspace 强专注；Dark Tech 可以更具沉浸感，但不是赛博霓虹或大面积高饱和渐变的同义词。

## 5. 设计分支 / Profiles（独立于产品的表达模式）

### A. MiMo / Research Editorial

**用途**：品牌叙述、个人首页、研究报告、文章、项目发布、长叙事。  
**典型表达**：偏纸面的中性底色；巨大的展示标题；细线连接的大段落；编号式内容索引；大段留白；有目的的背景字纹理；弱色彩强调。  
**不应**：把每页都制作成 hero + 三张卡片；不能为了“极简”删掉重要研究数据。

### B. MiMo / Developer Humanist

**用途**：开发者门户、API 站点、文档、安装/下载、CLI 案例、软件展示。  
**典型表达**：清晰大标题 + 直接可复制命令；黑白纸面风格与编辑元素；代码窗口、终端图和少量暖色功能强调；说明和图形交替。  
**不应**：把代码块当成装饰，牺牲真实可读性；不应复制官方终端 logo 或整套宣传插图。

### C. MiMo / Rational Humanistic Workspace

**用途**：个人工具、AI 对话、项目控制台、任务执行、插件设置。  
**典型表达**：白或浅灰画布、输入为焦点、轻边界卡片、克制阴影、有限视觉层级、帮助用户快速开始的建议操作。  
**不应**：让大字和装饰抢占长时间工作的界面；给所有按钮加动画。

### D. MiMo / Dark Tech Workspace

**用途**：长时间阅读或沉浸式 AI 工作环境、技术预览、暗色控制台。  
**典型表达**：深色中性底材、轻抬升面、节制高亮、清晰对比的文本与状态点、集中式操作焦点。  
**不应**：将暗色等同于炫目蓝紫光；过多发光容易偏离 MiMo 的人文克制。

> 推荐将这四项作为一个设计家族下的情境表达，**不是**四个彼此无关联、必须重复造轮子的独立组件库。Studio 官方只确认「理性人文/暗黑科技」的产品视觉风格；其他标签是为个人资源库研究而设。

## 7. 组件与交互的可复用词汇

不规定 MiMo 风格必须有固定组件。以下是**从真实模式归纳出的组件/场景原型**：

| 原型 | 设计行为 | 适合场景 | 风格身份 |
|---|---|---|---|
| Indexed Link Row | 左侧编号 + 标题/元信息 + 右侧箭头 + hairline | 论文、博客、文档、索引 | Research / 通用 |
| Hero Statement | 大字标题 + 少量说明 + 首要行动 | 品牌、发布、应用欢迎 | Editorial |
| Command Strip | 等宽命令 + Copy + 平台选择 | 工具、开发者页面 | Developer |
| Feature Split | 图像或 UI 裁图和文本交错 | Code / Desktop 说明页 | Developer / Product |
| Metric Story | 大数字 + 指标解释 + 细节支持 | 研究发布、案例 | Research |
| Docs Navigator | 搜索 + 分类折叠 + 内容目录 | 技术文档 | Developer |
| Prompt Composer | 输入框 + 上传/工具/模型控制 | Chat、AI 工作区 | Workspace |
| Suggestion Chips | 少量下一步建议，不喧宾夺主 | 欢迎页与空状态 | Workspace |
| Task Status | 执行中、结果可预览、可恢复/导出 | Desktop / Claw | Workspace |
| Scientific Interaction | 可操作模型 + 状态反馈 + 重置 | 研究可视化 | Research (拓展能力) |

**组件跨分支复用时优先保留功能语义**，再换用对应语义色、密度、边框和排版方式；不需要继承整套另一个产品的 UI。

## 8. 动效语言提炼

### 8.1 已有证据

- Studio 更新日志明确存在音频播放可视化优化与会话目录滚动交互；但没有给出 CSS/easing/时长。[R09]
- MiMo 材料研究页提供拖拽、方向键旋转、暂停与重置的分子结构交互；这是**有实际任务意义的动效**，不是单纯装饰。[R06]
- MiMo Code 页面有命令复制与系统平台切换等直接反馈型操作。[R03]

### 8.2 可提炼的 Motion Language（设计推导）

**Motion should clarify state and relationship, not demand attention.** 运动应解释界面状态、内容关系或任务推进，而不是为每一个元素制造存在感。

推荐的八种“可用动效能力”：

1. **Directional Hint**：箭头在 hover 轻微平移，突出下一步方向。
2. **Line Reveal**：目录分隔线或强调线按阅读路径展开。
3. **Section Enter**：阅读区块轻微位移 + 透明度变化，保持阅读连续。
4. **Surface Lift**：按钮/卡片短促的层级反馈，避免大幅悬浮。
5. **Command Feedback**：复制命令后 icon、标签与颜色短暂确认。
6. **Focus Transition**：输入、弹层、选项卡优先通过尺寸/透明度的局部变化传达状态。
7. **Data Motion**：数值变化、路径高亮、数据系列切换；强调准确与可暂停。
8. **Immersive Interaction**：仅在分子结构、音频波形等有意义的内容中使用连续动画；提供暂停/关闭。

**候选时长而非实测**：微交互 120–200ms；布局/局部切换 220–400ms；内容揭示 350–650ms。尊重 `prefers-reduced-motion`，非必要动画可以关闭。

### 8.3 不适合的误读

- 不等于每次滚动都淡入；大量重复淡入反而破坏内容的稳定感。
- 不等于必须使用视差、WebGL 或笔刷。那些只是针对具体叙事选择的资源。
- 不能凭静态截图推断缓动曲线、转场时间、滚动倍率。

## 9. 视觉参考组织方案（Claude Design 式）

每个参考条目建议记录：**来源网址、访问日期、页面功能、观察点、静态截图来源、是否官方、对应的设计规律、可以借鉴的抽象概念、不要复制的商标素材**。

### Positive References（典型正例）

- 官方研究主页：文本本身成为视觉构图，编号目录与科研叙事共存。[R02]
- 官方 MiMo Code：技术操作和品牌叙事同屏出现；命令 strip 是主行为。[R03]
- 官方 MiMo Code Docs：搜索、分组导航、可复制/查找文档。[R04]
- 官方 MiMo Desktop UI 截图：将主要输入置于中央，减少干扰。[R08]

### Boundary References（边界创新）

- 官方研究材料案例：复杂交互分子模型也能纳入理性的内容系统，不意味着页面必须永远纯静态。[R06]
- MiMo Code 的笔触纹理：人文材料可以与技术界面并置，但不必每一页都使用。[R07]
- Studio 的深色工作区：允许截然不同的背景明度，仍通过层级和任务驱动保持家族关系。[R09]

### Anti-patterns（为了保留 MiMo 气质而应警惕的倾向）

- 用无关 3D 球体、通栏紫蓝渐变替代真实内容；
- 将每块信息都塞进大圆角卡片、造成浮层泛滥；
- 过密的发光边框和纯装饰 hover；
- 把每个页面的排版锁死为 Hero + 三栏；
- 混入 Noema 的整套排版系统或 Lumina 的所有组件样式，使 MiMo 成为无辨识度的综合拼盘。

这些是本文的创作判断，并非官方禁止事项。

## 10. 响应式、可访问性与国际化

- **桌面（研究页）**：允许大标题和较宽的目录横排，但保持长文适宜列宽。
- **桌面（工作区）**：侧栏、输入和右侧预览可以共存，主要任务区需保持最大可读宽度。
- **移动端**：优先单列、折叠非关键侧栏；编号索引可以行内；确保 CTA 不因长英文术语溢出。
- **中英文**：字号层级不要依赖单一字体；标题换行需要分别检查中文短句和英文长词。
- **状态**：颜色不是唯一状态表达；复制成功、执行中、警告等提供文字/图标反馈。
- **动效**：支持减少动态效果、键盘聚焦、可暂停连续动画。

官方 Studio 更新日志确认深浅主题、中文/英文、PC/移动端的适配方向，但本文未逐设备测量所有细节。[R09]

## 11. 个人设计资源库的独立封装方式

建议先抽象成**跨产品的设计语言资源**，而不是直接存成 SP Theme。

```text
Personal Design Library
└── MiMo Study
    ├── DESIGN_LANGUAGE.md         # 研究和设计身份
    ├── design-tokens.candidate.json # 建议 Token（非官方）
    ├── reference-inventory.json    # 官网证据与状态
    ├── motion-language.md          # 交互/动效语言
    ├── specimen.html               # 独立可视化验证，不依赖 SP
    └── README.md                   # 使用说明与版本
```

这份设计语言可以用于未来个人主页、技术文档、AI 工作台和演示文稿。**SP 只负责在未来消费该语言资源的适配器**：语义样式 → SP 文本/形状；布局参考 → 幻灯片创作；动效能力 → reveal.js/GSAP；快照 → 可编辑离线 HTML。

本轮不修改 SP、Noema、Lumina 项目，也不强行决定 MiMo 在 SP 中对应哪两个分支。

## 12. Claude Design 式验证任务（待用户查看样板反馈）

建议用五个完全不同的任务，检验风格是否仍然可识别：

1. **研究首页**：一条醒目的英文主题声明、编号内容目录、文章展示。
2. **开发者发布页**：下载、命令复制、终端示例和功能解释。
3. **API 文档**：侧栏、层级目录、表格和高密度代码。
4. **AI 工作区**：输入、模型切换、工具结果和文件预览。
5. **数据实验页**：大数字、图表或模型操作、解释性文案。

**建议评审维度**：身份可辨识度（不依赖 LOGO）、跨场景稳定性、信息阅读效率、动效是否有意义、深浅方案兼容、易编辑与资源可复用。评审不需要无限循环：优先处理明显的结构/可访问性问题，再调整风格。

### 本轮研究待补证据

- 直接访问官网 CSS 后测量实际字体家族、H1 size、线条颜色、断点、rounded 值。
- 录屏分析 Code、Research、Studio 在滚动、Hover、导航、弹窗中的真实时间和缓动。
- 取得当前移动端官方站点截图并进行响应式比较。
- 获取或确认官方是否对外发布可复用视觉资产的许可；没有许可前只可抽象设计规律，不直接打包小米字体/Logo/图像。

## 14. 研究结论与下一轮建议

**MiMo Design Language 不需要固定为一个界面截图，也不应该直接复制小米官方品牌。** 建议作为一个独立的设计家族保存，最核心的四个可辨识特点是：

1. 克制但具有鲜明层次的文字与留白；
2. 章节编号、箭头和细分割构成的内容导航感；
3. 以工具本身作为视觉的一部分（命令、任务、输入、代码、研究图形）；
4. 理性、可靠，却不过度冷漠的情绪气质。

先用四个场景型表达（Research Editorial / Developer Humanist / Rational Humanistic Workspace / Dark Tech Workspace）做跨场景测试，再决定最终是否合并为两个可发布的分支。此时无须固化复杂 Schema、独立 Skill 或大量专属组件。

> 本文件是对 MiMo 官方网站设计现象的**研究与原创抽象**，并非小米官方授权设计系统。商标、Logo、插图、网页源码、字体与截图仅可在符合授权的前提下重新使用；个人设计资源库以自行生成的语义设计规范和原创视觉实现为主体。
