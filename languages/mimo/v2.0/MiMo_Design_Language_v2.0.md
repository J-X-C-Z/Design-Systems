# MiMo-inspired Design Language 2.0
## 理性技术人文：个人设计语言发布规范

**版本：2.0.0 · 日期：2026-10-10**  
**性质：可复用的原创个人设计语言，不是小米官方设计系统，不是官网像素复刻。**  
**归属：个人设计资源库 / MiMo。保持与 Lumina、Noema 的设计身份独立。**  
**本版范围：设计理念、两个分支、视觉基础、场景表达、组件状态、标志性动效、开放复用、AI 上下文、样例和验收。**

> 以清晰的结构承载复杂能力，以有人情味的表达保留人的主动权。

## 0. 这次完成什么

v1.0–v1.3 建立了观察、候选参数和多场景样板；v2.0 将它们收束成可以实际采用的个人设计语言。它不再把“必须先拿到官网全部 CSS”作为设计发布的前提：有来源的观察继续作为证据，必须自己做出的设计判断则明确承担为原创决策。

这是**个人设计语言的完整可复用基线**，不是对所有浏览器、所有商业应用和小米全部产品的认证。已交付源文件、可运行样例、参考图、动效实现和验证脚本；没有把 SP 主项目改造、真正 AI 服务接入、云端同步或小米官网复刻伪装为已完成。

本次沿用以下用户决策：

| 决策 | 在本语言中的含义 |
|---|---|
| Theme = 独特设计语言 | 主题有身份、空间和运动逻辑，不只是一组颜色 |
| Layout / Component = optional | 可提供布局和组件，不要求每次使用，也不禁止原创 |
| Motion = language | 先确定运动的意义，再选择资源和编排 |
| Switch = skin | 默认仅更换关联样式，保护内容、布局、显式覆盖和时间轴 |
| Reference = both | 每组原创参考提供截图和可编辑 HTML；另有场景源结构 |
| Reuse = shared | 资源可以跨主题引用，不要求继承整门设计语言 |
| AI 能力开放 | 提供身份、例子和能力，不强制十步流程或固定页面 |
| 跨产品优先 | 核心语言不依赖 SP；Web、文档、应用和 SP 各自适配 |

## 1. 从 Claude Design 借鉴什么

Claude Design 官方描述的设计系统涵盖颜色、字体、组件与布局模式；可从代码、原型、文档和品牌资料提取，并通过新项目检验。官方特别建议提供完成的真实案例，而不是只有颜色表。[R01]

本次将这一方法转化为六个**设计工作活动**：资料核对、稳定特征提炼、分支收敛、多场景表达、可运行资源制作、质量验收。它们不是要求每次 AI 改字都重走的流水线，也不是宣称本次实际在 Claude Design 应用中运行了任务。

与严格企业品牌系统不同，本人的个人设计语言优先保留创作自由。它可以清楚说明“为什么这样设计”，但不规定每一页只能使用现成组件。方法帮助我们作出有证据的判断，而不是成为新的约束机器。

## 2. 证据与设计决策必须分开

| 层次 | 已取得的依据 | 本版如何使用 |
|---|---|---|
| 官方文本观察 | Research 的重复字样和编号索引；Code 的命令与复制；Docs 的导航；Studio 的两种风格名称 | 提炼信息结构与交互意图，不反推精确字号 |
| 官方图像观察 | Code feature 图中的浅色终端、暖色底面、笔触式纹线和橙色强调 | 说明理性工具与人文材料可以共存；不打包原图 |
| 原创设计决策 | 色板、字距、边距、组件形式、曲线与时长、十种动效 | 作为个人设计语言的正式默认值，允许有意覆盖 |
| 本地验证 | 离线隔离 Chromium 的实际渲染、状态与读写测试 | 报告具体环境、样本和限制，不扩大为全平台认证 |

Research 页面确有编号、箭头和研究索引；Code 页面确有可复制命令和平台选项。[R02][R03] Studio 的 2026-07-23 更新确实使用“理性人文”“暗黑科技”两种名称。[R05] 官方研究案例还提供可旋转、暂停和重置的交互图形，说明运动可以服务内容理解，而不是纯装饰。[R06]

直接官网 CSS 与动态录屏未取得。本次不再用这一事实制造下一轮空转，也不把未知值伪装成测量值。所有原创 Token 的来源状态均与官网观察分开记录，详见 `evidence/references.json`。

## 3. 核心理念：理性技术人文

### 3.1 清晰不是删掉复杂性

研究、文档和工作台各有真实复杂度。设计需要揭示关系、顺序、证据和可操作入口，而不是为了看起来极简而删掉信息。一个结构清楚的高密度文档，仍然完全属于这门语言。

### 3.2 文字不仅传递信息，也组织空间

标题与编号形成第一阅读路径；正文承担解释；元信息标识来源、时间和层级；代码表达工程语义。字体不只是装饰，但“文字构成结构”也不意味着每一屏都铺满巨大字。

### 3.3 工具本身可以成为视觉主角

在开发者场景，命令、代码、文件和状态就是产品。工作区中，用户输入和结果就是主内容。它们必须可读、有正确状态、与实际操作相符；不使用无法执行的伪命令冒充真实安装流程。

### 3.4 平静不等于冷漠

纸面式底色、低强度材质、适量暖色和自然的文案，让技术表达有温度。暗黑分支保持同样的人的尺度，不靠蓝紫霓虹和发光边框来证明“科技感”。

### 3.5 运动解释变化，而不是索取注意力

有意义的运动回答：对象从哪里来？下一步在哪里？哪个状态改变了？新的证据如何连接原来的问题？动画结束后画面应稳定，用户应能停止或跳过它。

### 3.6 使用者保留主动权

主题切换不改写作品，导入不执行陌生代码，AI 不能把用户固定的样式偷偷恢复为默认。可编辑性、可迁移性、暂停与撤销不是视觉风格的附属品，而是这门语言对“人的控制”的表达。

## 4. 设计身份与可变部分

**稳定身份**是清楚的内容层级、编号与方向、克制的界面外壳、工程内容的直接性，以及解释关系的运动。**可变表达**包括配色、构图、内容密度、具体图像、边角、页面形式和资源组合。

因此，同一语言下可以出现几乎只有文字的研究封面、密集的 API 表格、深色任务工作区和可交互的结构示意。它们无需长得一样，仍可以共享一致的设计判断。

只要表达更适合内容，AI 可以创造新的栅格、图形和动效。判断标准不是“像不像某张参考图”，而是“是否保留身份、是否解释清楚、是否让用户保留控制”。

## 5. 两个分支与三个场景

### 5.1 理性人文 / Rational Humanistic

默认浅色分支，以温和的中性底面、较深的墨色文字、薄线和局部铜棕强调组织信息。表面层级主要由明度与边界形成，阴影不是默认的结构支柱。

阅读感受是开放、沉静、可靠。研究页可以使用大幅留白与文字结构；文档和工具页则应降低标题比例，增加可扫描性。人文材料可以作为局部表达，不需要每页都加纹理。

### 5.2 暗黑科技 / Dark Tech

深色分支使用多个可辨识的低饱和工作表面，文字保持清晰，强调保持局部。它不是对浅色图像简单反相，也不通过降低所有文字对比来制造高级感。

重点是专注和空间层级。在长期工作的界面中，活动区域、输入和状态变化更容易识别；亮色不占满画面，也不强制使用外发光。

### 5.3 场景不是分支

| 场景 | 内容的主角 | 主要表达 | 不应机械套用的做法 |
|---|---|---|---|
| Research | 论点、证据、来源 | 编辑式标题、编号、图解、段落节奏 | 每页固定 Hero + 三卡片 |
| Developer | 命令、代码、导航 | 可复制命令、终端、可定位内容 | 用花哨代码动画替代可读性 |
| Workspace | 意图、过程、结果 | 输入优先、紧凑外壳、明确状态 | 把宣传页的大标题搬进高频操作区 |

本版提供两分支 × 三场景的六组原创 HTML 参考。它们是取样验证，不是强制版式集合，也不是六套新的设计语言。

## 6. 色彩系统

色彩按语义分工。组件引用语义角色，不因当前显示某个色值就失去与主题的关联。

| 角色 | 理性人文 | 暗黑科技 | 用法 |
|---|---|---|---|
| Canvas | `#F6F5F1` | `#111814` | 全局底面 |
| Surface | `#FFFFFF` | `#18221C` | 工作表面与局部容器 |
| Raised | `#EBEDE7` | `#233129` | 次层级区域与安静背景 |
| Ink | `#17201B` | `#F0F3EC` | 主文字 |
| Muted | `#5B675F` | `#B0BDAF` | 次文字，不等于不可读 |
| Subtle | `#606C64` | `#A1B39F` | 弱标签，仍要求合理对比 |
| Rule | `#D0D5CC` | `#3C5143` | 装饰性分隔线，不单独承担控件可见性 |
| Control | `#7C897F` | `#829880` | 输入边界、需要被识别的控件 |
| Accent | `#96512F` | `#E3AF86` | 重点、方向、图形 |
| Accent soft | `#ECD9CA` | `#493A2D` | 局部强调底面 |
| Accent ink | `#703717` | `#FFDCC0` | 强调底面上的文字 |
| Action | `#1D2A23` | `#EDF1E8` | 主要操作表面 |
| On action | `#FFFFFF` | `#152019` | 主要操作上的文字 |
| Focus | `#315C9C` | `#A7C6FF` | 键盘焦点 |

成功、警告、错误另有语义色，不能仅用色相表达状态；同时提供符号或文字。具体数值统一以 `kit/design-language.json` 为源。

正文对比以 4.5:1 为检查目标；大字号文字的适用要求不同。[R08] 本版将主次文字、强调与状态色分别在多个表面上计算，共列出 50 组检查。装饰线不冒充达到 3:1 的交互边界，最终数字见验证报告，而不是由视觉印象决定。

**跨主题资源适配**默认映射语义色。例如证据流引用 `accent` 和 `rule`，所以在另一语言中仍能保留功能。需要保留原貌时，可以局部固定资源自己的分支，不让整页继承原主题。

## 7. 字体与中英文

本版采用系统无衬线与等宽回退栈，不随资源包分发任何字体文件，也不声称识别出小米官网的精确字体。

| 角色 | 默认起点 | 设计意图 |
|---|---|---|
| Latin display | 紧凑字距约 `-0.055em`，行高约 `0.98` | 在短标题中获得有力的文字形态 |
| 中文 display | 较舒展字距约 `-0.025em`，行高约 `1.14` | 防止把英文紧缩参数硬套中文 |
| Section heading | 清楚、较克制的展示层级 | 保持扫描效率，不与首屏争夺 |
| Body | 通常 16px、约 1.75 行高 | 阅读优先，允许按设备与内容调整 |
| Metadata | 通常 12px、等宽或次要声部 | 编号、来源、标签；不能承载大量正文 |
| Code | 等宽、自然换行或明确的局部滚动 | 保持代码本身可读 |

以上是默认的比例判断，不是必须保持的固定字号。展示样例中的小型图注与仪表标签是辅助信息，不可把它们的字号直接用作演示文稿正文。

系统字体在不同电脑上会有度量差异。跨设备交付需要检查换行、缺字和文字盒高度；不能因为使用同一 CSS 字符串，就承诺像素级相同。展示样例允许编辑中英文标题与长文案，用结果而非假设验证适应性。

## 8. 空间、布局与密度

**空间的责任是解释关系。** 较大间隔用于区分议题；较小间隔用于表达归属；对齐用于建立阅读路径；留白使焦点成立，而不只是让画面看起来昂贵。

默认间距词汇为 4、8、12、16、24、32、48、64、96px，正文阅读列以约 38em 为起点，页面容器以约 1440px 为宽屏上限参考。它们不是必须使用的固定网格。需要科学图解、空间结构或高密度报表时，允许完全不同的构图。

Research 可使用不对称内容区；Developer 让命令与解释相邻；Workspace 将主要任务面留给输入和结果。容器不能因为主题样式就自动把所有内容转成卡片。

本版样例的响应式断点为 600px 和 1000px，属于实现选择，不是小米官网断点。在较窄视口下按阅读优先级折叠布局，导航可以换行，控件仍可访问，不靠隐藏关键内容通过测试。[R10]

## 9. 图形、材料、图像与图标

本版交付四个原创、可编辑 SVG：Quiet Contour、Evidence Flow、Focus Frame、Index Rule。它们分别表达有温度的秩序、证据联系、局部焦点和方向导航。

Quiet Contour 从“理性工具与人文材料能够并置”的观察出发，用原创连续路径而不是复制官方笔刷图。它是可选装饰：有功能图表时，应优先让图表承担视觉主角。[R07]

摄影或插画可以进入这门语言，但需要与主题内容有关。图像边界、裁切和图注应清楚；不以随机 3D 球体自动替代复杂信息。头像、品牌标记、科学图片和外部资产须由具体项目确认使用权，核心包不捆绑它们。

图标以简单方向、状态和操作符号为起点，和文字共同表达意义。单独图标按钮需有可读名称；不因追求极简删除含义说明。

## 10. 组件语言：完整状态比数量重要

组件是可选资源。此版不建设一个覆盖所有业务的 UI 框架，而是把影响设计语言成立的关键原型做完整。

| 词汇 | 默认表现 | 关键状态 |
|---|---|---|
| Action | 深浅分支中的明确对比操作 | default、hover、focus、pressed、disabled、busy |
| Indexed row | 编号、标题、细线、方向 | hover 与 keyboard focus；多行标题 |
| Command strip | 可读命令、复制操作、明确结果 | success、denied、manual-copy fallback |
| Segmented tabs | 当前场景明确，可键盘移动 | selected、focus、roving tabindex |
| Text input | 边界清楚，提示与值分离 | empty、filled、focus、invalid、corrected |
| Composer | 输入为中心，工具在边缘 | editing、busy、canceled、result |
| Status | 文字与图标共同解释 | ready、running、warning、error、done |
| Disclosure | 局部展开而非跳离上下文 | collapsed、expanded、keyboard |
| Dialog | 局部层级变化 | open、close、Esc、focus return |
| Empty state | 告诉用户这里是什么及下一步 | empty、session-saved reference |
| Data table | 表头、行和单位有层级 | comfortable、compact；保持内容 |
| Fixed / linked style | 显示样式来源 | follows theme、explicit override |

组件规范详见 `docs/COMPONENTS.md`。主题中没有预制的组件时，用户与 AI 可以直接组合基本元素，不必先注册新组件才允许创作。

## 11. 动效语言与资源

本版的动效分成**意图、资源和编排**三层。意图说明为什么运动；资源提供可操作的实现；编排决定具体对象、顺序与故事。只有最后一层才属于具体页面。

### 11.1 五种标志性资源

| 资源 | 视觉机制 | 主要用途 |
|---|---|---|
| Index Trace / 索引描线 | 线条从阅读起点建立方向，编号跟进 | 索引、章节开启 |
| Type Unfold / 文字展开 | 按词组或整行遮罩揭示 | 核心论点、过渡标题 |
| Evidence Flow / 证据流 | 路径先建立联系，节点依次明确 | 推理流程、来源与结果 |
| Focus Aperture / 焦点开窗 | 在上下文内逐步打开焦点 | 局部发现、结构解释 |
| Quiet Reframe / 静默重构 | 同一对象在状态变化中保持身份 | 关系重排、局部连续变化 |

### 11.2 五种通用反馈资源

Directional Hint、Surface Resolve、Command Confirm、State Relay、Data Reconcile 分别处理方向、局部层级、操作结果、任务步骤和数据衔接。

默认时长为 micro 160ms、state 280ms、reveal 520ms、narrative 900ms；默认收束曲线为 `cubic-bezier(.22,.75,.2,1)`。路径或可观测进度可用线性变化。这些数值全部是本版原创调校，不是官网测量。

每个资源可以暂停、定位到某个进度、重播、直接完成、取消，并支持减少动态效果。默认不自动循环；不让一个箭头一直晃动来吸引注意。完整定义和 API 在 `docs/MOTION.md`、`kit/motion-resources.json` 与 `kit/motion.js`。

### 11.3 减少动态效果不是删除信息

系统偏好和页面开关都能减少非必要运动；此时直接到达可读的最终状态。任务进度仍保留文字，错误仍保留原因，图表保留真实最终值。用户交互产生的非必要运动能够关闭，是本版明确采用的可访问性方向。[R09]

## 12. Skin、Adapt、Redesign 的区别

**Skin** 是默认换肤。只更新主题关联的色彩、字体和表面表现；不自动改变文稿内容、元素坐标、页面顺序、分组和已有时间轴。其结果不等于“整个旧作品已经变成另一门完整设计语言”。字体换行仍可能变化，应检测而非擅自重排。

**Adapt** 是主动协调：例如保留外部 Evidence Flow 的逻辑，但让它采用目标主题的图形和节奏。它需要预览、说明改动和可撤销，不属于普通换肤的隐藏副作用。

**Redesign** 是主动重设计：允许重新构图、调整叙事与动画编排。只有明确请求这一类操作时，才可以改变作品结构。

本版 `MimoSkin.apply` 只修改根元素的模式属性，返回用于恢复前模式的函数。`resolve` 区分 `{token: ...}` 与 `{value: ...}`，按元素、页面、项目、分支、基础的优先级解析。`snapshot` 生成带版本的独立数据副本。这些是个人设计语言的参考工具，不是已经接入 SP 的 API。

## 13. 浅继承与跨主题共享

设计身份层保留“基础 → 家族 → 分支”的浅继承。作品中的项目、页面、元素覆盖属于实例层，不是新增主题家族。

同一资源可以有两个使用方式：**适配宿主**，通过语义变量获得目标主题的颜色、材质和默认值；**保留原貌**，在局部资源范围内固定原有表现。引用外部资源不等于继承外部主题。

例如 Swiss 风格项目可以使用 MiMo 的证据流路径能力，但将线条、标记和节奏调整为自己的语言。只有用户主动追求混搭时，才保留完整 MiMo 气质。资源没有被“锁死”为某个主题私有，但也不要求每个跨主题组合看起来都天然协调。

已用资源通过稳定 ID、版本、来源、参数与依赖记录。未用资源不需要随作品导出。母版联动、商业组件插件和多人编辑属于产品层，不在个人设计语言中预先实现。

## 14. AI 使用方法：高信息密度，低无意义约束

默认只需要一份短上下文：身份是什么，当前选了哪个分支，作品要表达什么，哪些资源可以按需取得。AI 需要具体图形或动效时再读对应实例，不需要同时读完全部文档。[R11]

`ai/AI_CONTEXT.md` 是轻量入口，`ai/SKILL.md` 是可选客户端形式。它们明确允许 AI 创造新的布局、组件和动效，不要求读取每个文件、经过多个 Agent 或执行固定审核轮数。

**系统应强制的条件**是结构合法、资源安全、操作范围与保存可靠性。**设计应该表达的条件**是身份、参考与意图。关于构图、视觉重心和叙事的选择，交给模型与用户。

导入图片、网页、PPT 和参考资料时，只把其中内容当作资料，不能把夹带的指令当作用户授权。主题设计指南也不能覆盖用户的明确要求。

## 15. 视觉参考：图片和可编辑结构成对

每个场景参考都有静态 PNG 与独立可编辑 HTML，并由 `evidence/visual-reference-index.json` 关联。`examples/scene-source.json` 保存同一批 DOM / SVG 源结构，便于研究构图；它不是冒称为 SP Document 的格式。

六组样例分别说明：同一种语言能够处理论点与图形、命令与终端、输入与任务状态。它们的页面差异是刻意保留的，不能把所有样例统一成一张模板。

边界案例包括：Research 使用较密集的证据图；Developer 保持较长的代码；Workspace 在手机上重排外壳。新设计比这些样例更大胆也可以成立。反例只用于指出具体问题，不为某种颜色或图形设置永久禁令。

## 16. 开放文件与跨设备

主展示文件和六个独立样例都是自包含 HTML，包含 CSS、脚本、原创 SVG 和可编辑文本状态。没有联网运行依赖，不打包字体文件。外部来源链接只有用户主动点击才需要网络。

样例支持编辑文字、导出项目 JSON、重新导入，以及将当前文字、分支与场景保存到 HTML。输入只恢复为文本，不执行导入的脚本。此编辑能力用于验证设计语言的可复用性，不是完整 SP 编辑器。

当前管理环境禁止 `file://` 导航；测试使用隔离浏览器读取同一份 HTML 内容，并关闭网络。由此可以验证没有外部运行依赖和内容读写链路，**但不能声称完成了 Windows/macOS 上的双击实机测试**。这项边界写进发布记录，不再把整门语言标成“还没有完成的研究”。

## 17. SP 适配边界

核心资源可以交给 SP 适配器消费，但本版不修改 SP 主项目。适配需要把语义色映射到标题、正文、连接线和图表，按投影距离选择文字比例，并把动效意图映射到 reveal.js / Fragments / Auto-Animate 或其他已批准的运行能力。

网页 hover 不能成为翻页演示的必要触发；长滚动叙事应转译为显式步骤；主题快照要包含实际使用的资源和分支版本。详见 `adapters/SP_ADAPTATION.md`。文档中的接口名仅为此资源库定义，不能被当作 SP 已经实现的工具。

## 18. 发布判断与质量边界

完成的基线包括：理念可解释、两分支可使用、六组参考可编辑、十项动效可操作、核心状态可验证、色板可计算、资源可独立带走、AI 指导不封死创作。

测试不是审美结论，也不是用户已经主观确认的记录。可读性、结构和技术检查通过后，用户仍可按个人审美改变表达；这属于正常设计演进，不必退回“候选参数无穷研究”的状态。

后续新增图形、组件和动效应作为同一语言的增量，不因为颜色或一个页面变化就重建另一套同名资源库。与 Lumina、Noema 的边界继续保持；共享通用资源不意味着合并身份。

## 19. 阅读和使用顺序

设计者先看主 HTML 与六场景总览，再按需阅读本手册。AI 先读短上下文，开发者从 `kit/` 和 `docs/INTEGRATION.md` 开始，SP 适配者读独立的适配说明。

不要求所有使用者从头阅读整套文档，不要求每次修改都完成全部测试。改变核心样式或导出模型才运行相关回归；改动一段文案可以只检查相关场景。
