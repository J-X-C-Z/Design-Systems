# 瑞士信息设计研究与原创设计语言

Swiss Information Design Study 1.0 · 2026-10-10

本资源包为个人设计语言资源库中的独立研究。它把信息编排方法转译成可用于研究报告、目录、数据展示和文化海报的原创语言。它不是历史流派的统一官方规范，也不是 Helvetica、Vignelli、Müller-Brockmann、Swissted 或 Swiss Typefaces 的授权系统。

所有 Hex、字号、网格列数、间距、断点、动效时长及组件 API 都是本包提出的 D 级候选值。历史来源只支持明确标注的观察，不为候选数值背书。样板不依赖 SP、MiMo 或其他设计家族，也没有修改这些项目。

## 0 核心判断

瑞士信息设计的可迁移价值，在于让内容的关系成为可见的秩序。先确定读者需要比较、寻找、理解或行动什么，再决定对齐、尺度、密度和节奏。把“白底、红块、大号无衬线”当成全部语言，会得到看似熟悉、实际无法处理复杂信息的外壳。

本包保留六项不变量：

1. 内容先于版式。相同信息的编号、名称、时间、数量与来源保持稳定，跨场景只重排优先级。
2. 对齐能够被解释。每条主要边缘服务阅读、比较或分组，避免每个模块另建一套坐标。
3. 层级是相对关系。标题、正文、注释和行动的尺度差需要与具体任务匹配。
4. 空白有职能。它标示组界、转换节奏或提供图文呼吸空间，不能靠放大空白掩盖缺失内容。
5. 色彩有语义。强调、选择、警示、数据类别与文化表达分别定义，不能让同一种红色承担互相冲突的任务。
6. 形式可以变化。两分支保留数据模型、文字角色和对齐逻辑；文化表达允许更强张力，信息工作界面优先稳定与可读。

推荐以“信息秩序”为默认分支，以“文化海报”为按场景启用的表达分支。两者是同一语言的两种工作状态，不是两套互不相干的皮肤。

## 1 方法与证据边界

### 1.1 对齐已有资源库的方法

参照既有 MiMo 研究文件的流程与封装方式，采用 Collect → Observe → Distill → Cluster → Translate → Validate。继承研究严谨度与存放结构，不继承 MiMo 的视觉结论。

- Collect 收集：历史方法文本、出版方书目与图像、当代字体厂商、设计师自身作品说明、现代交互技术案例。
- Observe 观察：逐条记录文本证据与实际看过的图像，分开描述“页面提供什么”和“我们决定怎么设计”。
- Distill 提炼：把可迁移规律与某位作者的个人偏好分开，避免用一个项目代表整个传统。
- Cluster 聚类：将稳定查找和文化传播分成两个优先级不同的场景，而不是按颜色分家。
- Translate 转译：提供语义 token、内容契约、组件行为、动效状态图、响应式规则和明确反例。
- Validate 验证：同一套四条活动数据进入研究、目录、数据、海报四种结构，检查身份、事实和可用性是否同时成立。

### 1.2 证据分级

| 等级 | 可证明的内容 | 本包使用方式 |
|---|---|---|
| A 第一方文字 | 作者、出版方、字体厂商对自己的作品或方法的说明；W3C 的规范解释 | 支持明确事实，附来源与定位 |
| B 第一方视觉资产 | RIT 提供的 Canon PDF、Niggli 书封及 Swissted 官方作品图片 | 只描述实际查看的图形关系；不反推出生产 CSS |
| C 辅助解释与实现示例 | Sulflower 配方；Codrops 交互示例 | 帮助比较与提出问题，不作为历史事实的唯一来源 |
| D 本包原创候选 | 全部 token、分支、组件与样板代码、演示数据 | 可修改、需验收，不冒充官方参数 |

“第一方”针对具体主张判断。Swiss Typefaces 是其字体产品的一手来源，但它的历史回顾不等于独立历史学术论证。Codrops 是其示例的一手来源，但不是瑞士平面设计的历史证据。

### 1.3 关键纠偏

Sulflower 配方把 Helvetica、单强调色、零圆角、静态动效打包成一种快速风格提示。[R06] 可以用它启动受控实验，但不能把其中的限制当成整个传统的边界。Swissted 作者明确说明作品使用 Akzidenz-Grotesk。[R03] 当代 Suisse 家族也包含不同用途的字体。[R05] 因此，本包把“Helvetica 必选”“绝对不能动”“不能表达情绪”从语言核心中排除。

### 1.4 本轮已读与未读

完整读取已有 MiMo 研究规范 365 行。研究来源读取范围与图像核验状态列在 reference-inventory.json。Canon 重点读取网格、字体关系与色彩相关段落，并查看 PDF 第 21、27 页图像；未逐页审阅全部作品。没有复制第三方源代码，没有打包第三方字体、商标、海报或书页。本轮浏览器启动受环境权限限制，未完成真实浏览器渲染。已执行的静态、数据与模板函数核验和未完成范围详见 VALIDATION.md；不能把这些检查当成视觉、键盘或来源网站审计。

### 2.1 来源观察与原创转译之间的距离

Canon 的网格章节强调按内容选择结构，并让文字与图形建立一致关系；相应书页使用细网格说明模块。Niggli 书封呈现双语标题和网格线。[R01][R02] 本包据此提出“可解释对齐”这个工作原则；具体采用 12/6/1 栏、4 px 空间单元、1/3 px 线条，完全是针对当前屏幕样板的原创选择。

文化海报分支只继承“对同一事实重新建立阅读节奏”的思路。它的构图、图形和文案均为本包原创；没有描摹 Swissted 的单件作品。

## 3 内容模型先行

### 3.1 必须先回答的四个问题

开始任何页面前，用一段话写清：谁读、先找什么、随后比较什么、最终能做什么。如果答案只是“显得瑞士”，应退回内容整理。

示例任务：读者正在浏览一个虚构的设计研究日，希望理解主题、找到某个单元的时间、比较各单元的时长，并在宣传海报上迅速确认活动名称和日期。样板不包含报名、付款或真实预订行为。

### 3.2 本包验证用数据

活动名称：信息的路径 / Paths of Information。日期：2026 年 11 月 14 日。地点：示例研究室 A。所有内容、容量和安排均为原创演示数据，不对应真实活动，也不是用户的日程。

| ID | 名称 | 开始时间 | 时长分钟 | 示例容量 |
|---|---|---:|---:|---:|
| 01 | 读图与寻路 | 09:30 | 40 | 64 |
| 02 | 网格与目录 | 10:20 | 45 | 48 |
| 03 | 字体与语言 | 11:20 | 50 | 72 |
| 04 | 运动与状态 | 13:30 | 40 | 56 |

四条数据的总时长为 175 分钟，总容量字段相加为 240。容量相加只用于样板统计，不代表同一批人的实际参会总数。样板明确标注这些限制，不以演示数字作实证研究结论。

### 3.3 跨场景内容契约

- 主键永远是 ID，排序不能改变 ID。
- 名称与时间不能为了构图被改写；海报可将换行位置作为表现手段。
- 图表切换时，单位、刻度上限和文本值一起变化。
- 目录以时间查找为主，数据视图以数量比较为主，研究视图以问题与方法为主，海报以主题识别为主。
- 缩小屏幕可以改列数与阅读顺序，不能静默删掉必要字段。
- 所有重排同时更新 DOM 顺序，让键盘与阅读顺序一致。

## 4 Design DNA 与可检验标准

### 4.1 建立少量清楚的对齐轴

主标题、导语、目录与正文不是分别居中或任意悬浮。先选一个主要起始轴，再允许一条次级注释轴。复杂内容可增加数据轴，但新增轴必须与比较关系对应。检查方法：隐藏色彩与图形后，仍能看出主要分组与阅读路径。

### 4.2 层级靠差异，不靠堆叠

显示标题只承担一次主张。章节标题负责转场；正文承担解释；元信息负责定位；按钮负责动作。避免同一屏上五种字号都争当标题，也避免让标题与正文只差 1–2 px。选中态不应靠字重轻微变化独自表达。

### 4.3 不对称需要平衡

不对称是视觉重量的调配，而不是把所有内容推到边缘。大字占据一侧时，对侧应由足够的内容、几何体或有意义空白维持张力。移动端无法保留左右张力时，以先后节奏替代，不压缩成难读的双列。

### 4.4 关系比容器更重要

同一组数据优先用基线、列与规则线组织，不默认每项包一张圆角卡片。容器仍可用于真正独立的操作区域、错误与详情。零圆角在此包是视觉候选，不是对原生表单或系统控件的历史裁决。

### 4.5 语气准确而非冷漠

标签直接描述内容，例如“按时长排序”“恢复默认”。帮助文字说明结果，不把读者当成技术专家。文化场景可有富于节奏的短句，但操作控件必须清楚；“理性”不能成为省略解释或拒绝友好的借口。

### 4.6 去掉识别符后仍可辨识

不用国旗、瑞士十字、历史海报临摹或品牌字体做捷径。把名称和颜色隐藏后，本包应仍保有编号、共同对齐轴、强弱尺度、事实性标签、平面几何和节制反馈。这是后续修改的家族一致性测试。

## 5 五个设计维度

### 5.1 色彩及其角色

| 角色 | 候选值 | 使用范围 | 禁止误用 |
|---|---|---|---|
| canvas | #F4F2E9 | 样板纸面与内容背景 | 不宣称为历史纸色或官方测量 |
| surface | #FFFFFF | 控件与局部独立内容 | 不必为每一行加白卡片 |
| ink | #151515 | 标题、正文、数据 | 长文不反复切强调色 |
| inkMuted | #575750 | 注释、说明 | 不能用于唯一状态线索 |
| rule | #B8B7AE | 装饰性分隔 | 不能独自标示必需的控件边界 |
| ruleStrong | #151515 | 表头、主要组界、输入边界 | 不让每条规则线都相同粗重 |
| accent | #B92F22 | 选中、索引、文化表现面 | 不能同时无说明地表示危险 |
| onAccent | #FFFFFF | 强调面上的文字 | 每种新强调色都须重算对比 |
| focus | #173DB5 | 键盘焦点 | 可以与品牌强调色不同 |
| success | #245D40 | 成功文字与图标 | 不只靠绿色 |
| caution | #765114 | 警示文字与图标 | 不用浅黄字配白底 |

信息秩序默认中性底、深色文字、局部红色。文化海报允许红色成为大面积底色，但通过白字和黑色几何结构保持对比。真实数据若有多类别，允许扩展分类色，并同时使用标签或线型。单强调色是默认节制策略，不是阻止表达真实类别的约束。

本包不提供未经测试的暗色主题。未来暗色适配应独立验证表面层级、边线与状态，不可机械反色。

### 5.2 字体角色和中文适配

本地替代栈：Arial、Helvetica Neue、Helvetica、Noto Sans CJK SC、PingFang SC、Microsoft YaHei、sans-serif。浏览器使用用户已有字体；没有下载、内嵌或依赖 CDN 字体。系统字体在不同平台会改变行宽和换行，这属于可预期差异。

| 角色 | 桌面候选 | 中文处理 | 使用目的 |
|---|---|---|---|
| display | clamp(3rem, 8vw, 8rem) | 行高 1.05–1.12，中文不使用拉丁负字距 | 一个主张或活动名称 |
| heading | clamp(1.75rem, 3vw, 3rem) | 中英混排适度放宽行高 | 章节与重点 |
| body | 1rem / 1.65 | 长中文段落控制到约 28–40 个汉字宽 | 持续阅读 |
| meta | 0.8125rem / 1.45 | 不全大写中文，不过度加字距 | 日期、编号、标签 |
| data | 1rem / 1.35 | 数字使用 tabular-nums | 对照、表格、图表 |
| index | 2.25rem / 1 | 编号为真实顺序，不充当装饰 | 定位与回忆 |

字号只是初始值。元信息在重要场景可升到 14–16 px，不为“精致”牺牲阅读。拉丁展示字可采用 -0.04em；中文标题保持 0 或略正字距，避免笔画拥挤。表格的日期、时间、ID 采用不换行；正文允许自然换行；长英文术语使用 overflow-wrap。

若未来购买 Helvetica、Akzidenz-Grotesk 或 Suisse，需按实际用途核对授权与字形覆盖。本包未评审或接受任何字体许可。

### 5.3 网格、空间与比例

候选空间单位为 4 px；常用阶梯 4/8/12/16/24/32/48/64/96。采用这一梯度是为了减少偶然值，并不要求所有行高和图形必须整除 4。

桌面以最多 12 栏作为构图参考，研究正文可用 8+4 或 7+5，目录按真实字段分轨；中屏以 6 栏参考，窄屏转单列。网格 overlay 仅用于检查，不在每个正式输出中常驻。宽度由阅读目的决定，不把 12 栏误解为必须塞 12 个等宽盒子。

用三种间距表达三个关系：组内 8–16，组间 24–32，章节间 48–96。若组内间距大于组间间距，先修正关系再装饰。

显示标题可以跨多个模块，但正文行宽仍受控。样板中文正文使用可读列；数据图表按行组织，不用为宽屏强造过长正文。

### 5.4 材质与图形

默认平面、无模拟玻璃、无浮雕、无大面积投影。纸面色来自候选 palette，不制造假扫描脏点。图形由线段、方块、圆弧和数字组成，每个图形在注释中说明职能：分组、方向、数量或主题隐喻。

照片可以进入系统，只要说明来源、裁切与内容职能。当前包不需要照片，因此不为“丰富”加入库存图。文化分支中的几何体为原创示意，尺寸不暗示真实测量。数据图形则严格由演示数据生成，两种类型不能混淆。

### 5.5 情绪与表达强度

信息秩序：清楚、可信、平静、可比较。文化海报：集中、鲜明、有节奏、有张力。两者都避免无目的噪声。文化分支可以有情绪，但日期、地点和内容不能成为无法读出的边角装饰。

## 6 两个分支的完整契约

### A 信息秩序 Information Order

用途：研究、档案、目录、文档、图表与长期使用的工具界面。

- 内容优先级：任务名称 → 当前状态或摘要 → 可扫描的结构化内容 → 证据与说明。
- 构图：稳定起始轴，编号栏，宽度适中的阅读列；表头与数据列垂直对应。
- 尺度：主标题强，正文完整，指标只在有解释时放大。
- 色彩：中性面占主导，强调色用于一项明确功能；多种状态用文字补足。
- 动效：少量位移解释重排，控件反馈快，不延迟信息出现。
- 组件：索引行、数据带、带定位的注释、透明而可恢复的筛选。
- 退出条件：若需要长时间阅读却出现满屏巨大字、动效抢先、隐藏关键字段，则应削弱表现强度。

### B 文化海报 Cultural Poster

用途：活动传播、专题封面、展览、短篇观点、社交图、演示的章节起始页。

- 内容优先级：主题 → 时间或核心事实 → 描述 → 次要安排。
- 构图：大字与一个明确几何母题形成张力；上下或左右不对称，但共享少量对齐轴。
- 尺度：一个主要尺度跃迁；不是每行文字都最大。
- 色彩：允许大面积强调面；至少保留一个稳定信息区。
- 动效：可提供一次用户触发的排版重构；静态时仍应成立，不用自动循环吸引注意。
- 组件：主题字场、信息脚注带、编号节目单、原创几何构成。
- 退出条件：如果用户要反复比较几十条记录，回到信息秩序；不要把海报布局硬套成工作台。

### 6.1 两分支共用与变更的边界

共用：ID、数据模型、来源记录、字体角色、基础空间梯度、状态语义、焦点样式、减少动态规则。可变：标题比例、强调色面积、几何图形的主导程度、空白分布、章节节奏。不可为了分支转换而改变事实、遗漏单位或破坏阅读顺序。

### 6.2 决策流程

1. 先问页面需要频繁查找还是单次识别。频繁查找选 A，单次传播可选 B。
2. 再问当前信息是否有比较关系。有则保留列、对齐和单位，不因海报化而拆散。
3. 判断是否存在复杂操作。若有，操作区仍采用 A 的稳定控件。
4. 最后决定表达强度；不要从“想用红底”倒推内容架构。

## 7 Token 与适配层

详见 design-tokens.candidate.json。分为基础值、语义值、排版角色、布局、两分支及动效。候选 JSON 是独立可读的本包格式，不声称与 DTCG 或任何产品 schema 完全兼容。

使用时先映射语义角色。例如 accent 应映射到“本场景强调”，不要直接全局替换所有红色；inkMuted 不是 disabled；rule 不满足所有控件边界需求。密度切换只调整间距、布局列数与行高，正文不低于 16 px，命中区域不跟着视觉密度无限缩小。

一次适配应保留至少四种输出：语义 CSS 变量、文本角色表、布局说明、交互状态表。PPT 或 SVG 输出可以重用角色与结构，不能将屏幕 px 直接当印刷 pt；应根据观看距离重新确定尺寸。

版本约定：修正描述而不改视觉契约是 patch；增加可选能力是 minor；改变语义、删除 token 或破坏已有内容模型是 major。当前 1.0.0-candidate 是原创研究基线，等待具体场景验证，不是生产组件库承诺。

## 8 可选组件词汇

| 组件 | 内容要求 | 交互和状态 | 不适合的用法 |
|---|---|---|---|
| Indexed Row | ID、标题、时间或类型、可选说明 | 整行不制造多个重复焦点；详情有明确按钮 | 只把编号放大而不给信息 |
| Evidence Note | 主张、来源 ID、可信等级、限制 | 原生链接，可键盘访问 | 用微小灰字藏住限制 |
| Metric Band | 值、单位、范围、解释 | 数据变化同步单位与文本 | 无单位大数字装作成果 |
| Compare Bars | 标题、数值、共同尺度、文本替代 | 可选排序与指标切换 | 截断轴制造虚假差距 |
| Grid Inspector | 列数/间距说明、显示状态 | overlay 不挡点击且不进入阅读顺序 | 把网格线当正式内容 |
| Density Switch | 当前密度、效果说明 | 保持选择与筛选，不改内容 | 把密集等同更小文字 |
| Layout Reorder | 稳定 ID、排序键、结果数量 | DOM 顺序变化，短时 FLIP，可减少动态 | 动画后 ID 与内容错配 |
| Poster Field | 主标题、主事实、次信息、母题 | 原生文字，支持打印与复制 | 全部文字压成一张不可读图 |

本包样板不是完整 UI kit，不为每个应用提供登录、支付、表单校验或复杂数据编辑。适配者应只取需要的词汇。

## 9 动效语言

动效是本包为屏幕媒介提出的扩展，不是“发现了历史瑞士动效规范”。Codrops 提供现代网格重排的技术参考，本包没有加载它的库或复制它的代码。[R07]

允许的运动应回答至少一个问题：什么改变了、它从哪里来、当前选中了谁、结果排序为何改变。默认不用加载开场、循环漂浮、视差、数值滚动开奖或离屏隐藏内容。

- 状态反馈：120 ms，颜色或下划线改变，不移动命中目标。
- 内容切换：160 ms 小幅透明度反馈，内容立即可用。
- 关系重排：320 ms，保留身份、把旧位置连接到新位置。
- 减少动态：立即完成布局与状态更新；仍提供文字提示。

全部候选参数详见 motion-language.md。减少动态既尊重系统偏好，也允许用户在样板内主动开启；系统要求减少时不由控件强行打开动画。快速重复操作会取消旧动画后按最新状态呈现，不排队回放过时动作。

## 10 正例 边界与反例

### 10.1 可接受的正例

- 一条目录行内，ID、名称、开始时间与时长沿固定轨道对齐。用户不用逐行猜测哪个数字是时间。
- 研究页有醒目题目，但结论、方法与限制完整；大字没有取代解释。
- 图表排序后保留稳定 ID，辅助文本明确“已按时长降序”；相同数值保留 ID 升序，避免无原因跳动。
- 海报夸张主标题，同时保持日期与地点可读，几何图形完全原创且不冒充数据。

### 10.2 有理由的边界创新

- 可使用超过一种数据类别色，只要含义明确并有标签与足够对比。
- 可在长文适配中试用有衬线正文，前提是家族关系与阅读效果被验证；当前样板不包含此扩展。
- 可以有网格重排动画，前提是静态状态、减少动态和快速重复操作都可靠。
- 可让中文成为主视觉，英文是次声部；不要求为了历史感把中文缩成注释。
- 表单采用原生下拉菜单，外观因操作系统不同略有差异，是可接受的可用性权衡。

### 10.3 应纠正的反例

| 误读 | 造成的问题 | 修正 |
|---|---|---|
| 任何页面都是红黑海报 | 任务密度与阅读时长失配 | 按场景使用分支 |
| 把 12 栏当 12 个盒子 | 信息单位被平均化 | 让字段与阅读路径决定跨度 |
| 每块内容都加粗黑框 | 组界消失，页面噪声增加 | 只对真正组界用强规则线 |
| 极细小灰字才高级 | 限制与注释不可读 | 提升字号与对比 |
| 整页全大写英文 | 词形降低辨识，中文变次要 | 按语义选择大小写 |
| 字体同名即完全一致 | 字宽、授权、字形覆盖不确定 | 验证实际环境与 fallback |
| 网格必须永远显示 | 工具变成表演 | 将网格作为可选检查层 |
| 海报元素直接当图表 | 读者误认数量关系 | 分开标记示意与数据 |
| 鼠标看起来能用即可 | 键盘与触屏遗漏 | 检查焦点、触点、语义 |

## 11 响应式 可访问性与国际化

### 11.1 内容重排规则

1200 px 以上允许旁注与主内容并列；720–1199 px 收缩展示标题并简化旁注；720 px 以下改为单列，主标题、说明、控件、结果按任务顺序出现。320 px 是本包额外压力测试宽度，不是唯一移动设备代表。窄屏的目录将次要字段放到第二行，保持时间与名称的可扫描性。

不使用固定高度锁死中文段落。控件换行后仍保持标签对应。表格若确实具有二维关系可局部横向滚动，但本样板的四字段表在窄屏可完整阅读，不要求整页横向移动。

### 11.2 对比与焦点

本包按 W3C 说明检验普通文字至少 4.5:1、大字至少 3:1 的常见适用阈值，并保留各语义色配对的实算记录。[R08] 可见焦点采用蓝色外轮廓与间距，不只靠按钮换色。装饰性细分隔线与可交互控件边界使用不同角色。

### 11.3 动作和状态

所有控件用原生 button、input、select，标签明确。选择用 aria-pressed 或原生选中语义，结果提示使用 polite live region。筛选后有零结果状态和清空方法。详情开合不把键盘焦点移到不存在的位置。控件候选最小高度 44 px 是本包更保守的设计目标，不把它误称为 WCAG 2.2 AA 的统一 44 px 要求。[R11]

### 11.4 运动与重排

系统 prefers-reduced-motion 为 reduce 时，所有非必要位移停用。用户可主动开启“减少动态”；关闭该控件仍遵守系统设置。屏幕宽度变化时只做正常重排，不触发大范围过场。W3C 的交互动效说明可作为进一步评审依据；这不构成全站 AAA 声明。[R09][R10]

### 11.5 中文与双语

中文主标题和英文副标题可以不同尺度，但不把英文误设为唯一 h1。中文文本标记 zh-CN，英文短段标记 en。时间和单位保持清楚，例如 40 min 不在数字与单位之间断行。中文括号、顿号和标点需检查换行；使用系统 CJK fallback 时还需在实际目标平台复核。

### 11.6 本轮没有声称完成的验收

没有真实用户可用性研究，没有屏幕阅读器听读全流程，没有真实 iOS/Android/Safari 设备测试，没有色觉障碍用户评审，也没有印厂打样。当前验证说明这些缺口，而不把自动化检查包装成全面认证。

## 12 四场景验证任务

| 场景 | 同一内容如何转译 | 完成任务 | 失败信号 |
|---|---|---|---|
| 研究 | 主题、问题、方法、四单元、限制 | 理解研究对象与假设 | 只有漂亮标题没有论证 |
| 目录 | 四条记录、搜索、排序、详情 | 找到指定单元时间 | 排序改掉 ID 或字段丢失 |
| 数据 | 时长/容量指标、共同尺度、明细表 | 比较数值并理解单位 | 柱长不对应数值或无文本替代 |
| 海报 | 主题主视觉、日期地点、四单元 | 快速识别主题与安排 | 字被裁切、时间不可读 |

每个场景都可切换 A/B 分支。通过并不要求两种分支在每个场景同样合适；它验证共同语言能否承载内容，并帮助看清取舍。密集目录更适合 A；B 在研究与数据场景只加强题头和节奏，不能把数据变成不可读装饰。

## 13 独立封装与未来消费

资源库存放于 /设计语言资源库/瑞士信息设计，与 MiMo 同级。主文件是 DESIGN_LANGUAGE.md，配套候选 token、来源清单、动效文档、单文件 HTML 样板、数据 fixture、验证记录与 README。ZIP 保留完整可复用目录，第三方参考资产仅保留 URL，不随包分发。

网页适配：把语义 token 映射为 CSS 自定义属性，保留稳定 ID 与控件状态。演示适配：把 display、heading、meta 映射为文字角色，把布局图映射为可编辑形状。文档适配：收紧展示尺度，保留层级、图表与来源。任何产品（包括未来 SP）只通过独立适配层消费，不把本研究目录写成产品主题配置。

### 13.1 可复用的设计任务提示

“使用瑞士信息设计语言。先列读者任务与信息模型；选择信息秩序或文化海报分支；以共同对齐轴、明确文字角色和有语义的强调色建立布局。保留真实名称、单位、ID 和来源。标题可以强，但不得裁掉关键信息。不要复制参考作品；所有 token 视为候选。仅为状态与关系使用动效，并提供减少动态。至少用一个窄屏与一个长文本情况验证。”

### 13.2 使用后的修改顺序

先改信息缺失，再改结构和对齐，再改可读性，再改颜色与微动效。不要先调动效曲线去掩盖错误阅读顺序。用户反馈应对应到具体场景与角色，例如“目录时间列不易比较”，而不是直接把全系统改成另一套风格。

## 15 当前结论与发布条件

本包建立了一套可运行、可检查、可替换内容的原创研究基线。其核心资产是内容关系、角色契约与取舍方式，视觉样板用于证明这些关系在不同密度、分支和场景中仍能工作。

进入真实项目之前，仍需做三项与具体项目绑定的验证：使用真实最长文案和最大数据量；在目标设备与授权字体上检查排版；由目标读者完成实际查找、比较与行动任务。没有这些步骤，就不应将候选 token 宣布为全场景最终规范。
